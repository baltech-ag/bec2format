# RequiresBusAddress header no longer derived from config

## Context

The bus-address header of BEC2 files is renamed and extended (TS-965,
BMM-27). The creator of a BEC2 file sets it, not bec2format.

Until now, `Bf3File.derive_comments_from_config()` wrote the hardcoded
`RequiresBusAddress: Yes` whenever the config value `0x0620/0x20`
(`Custom/AdminData/RequiresBusAddress`) was set. Otherwise it removed the
key, which also deleted a header the caller had set on purpose.

## Changes

- `bec2format/bf3file.py`: remove the `RequiresBusAddress` block from
  `derive_comments_from_config()`. The method no longer adds or removes a
  bus-address header, so any header already in `comments` is kept.
- `tests/test_derive_comments_from_config.py`:
  - a set config value `0x0620/0x20` no longer produces `RequiresBusAddress`;
  - bus-address headers set by the caller survive the call.
